# Integration Guide: Mayor Performance Intelligence System

This application currently operates as a **production-ready shell**, utilizing a simulated data layer and mock API routes to demonstrate real-world data flow. To transition this system into a fully functional SaaS product for live deployment, you must integrate several external services.

This document outlines the required external APIs, their purpose, and exactly where to implement them within the codebase.

---

## 1. OpenAI API (AI Intelligence & Newsletter Generation)

**Purpose:**
Powering the dynamic "AI Insights Platform" and the automated drafting capabilities in the "Newsletter Builder".

**Required API Keys:**
*   `OPENAI_API_KEY` (Get from [platform.openai.com](https://platform.openai.com/))

**Where to plug it in:**
1.  **AI Insights (`/src/app/api/insights/route.ts`)**: Replace the mock `setTimeout` and static `mockInsights` response with a call to the OpenAI API. Construct a prompt using the current metrics from the database to generate dynamic, contextual insights.
2.  **Newsletter Builder (`/src/app/api/newsletter/generate/route.ts`)**: Replace the static string generation with an API call to `openai.chat.completions.create`. Pass the `theme` and `segment` parameters into the prompt to generate tailored content.

---

## 2. Mailchimp API (Campaign Distribution)

**Purpose:**
Managing constituent mailing lists and actually sending the generated newsletters from the "Newsletter Builder".

**Required API Keys:**
*   `MAILCHIMP_API_KEY`
*   `MAILCHIMP_SERVER_PREFIX` (e.g., `usX`)

**Where to plug it in:**
1.  **Newsletter Sending (`/src/app/newsletter/page.tsx`)**: You will need to create a new API route (e.g., `/api/newsletter/send/route.ts`).
2.  In this new route, use the `@mailchimp/mailchimp_marketing` npm package to create a campaign and send it using the `content` generated by the user.
3.  Replace the mock "Send to Constituents" button click handler in the UI to call your new API route.

---

## 3. OCR Service (Data Upload & Parsing)

**Purpose:**
Extracting structured data from screenshots, PDFs, and unstructured documents uploaded via the "Data Upload & Input" page.

**Recommended Services:**
*   **AWS Textract** (Requires AWS credentials)
*   **Google Cloud Document AI** (Requires Google Cloud Service Account JSON)

**Where to plug it in:**
1.  **Upload Handler (`/src/app/api/upload/route.ts`)**: Currently, this route mocks the delay. You must implement logic to:
    *   Accept the multipart form data.
    *   Upload the raw file to an S3 bucket or Google Cloud Storage (temporary holding).
    *   Pass the file URI to your chosen OCR service.
    *   Parse the returned JSON to extract relevant civic metrics and update the database (`src/lib/mock-db.ts` -> Real DB).

---

## 4. Social Media APIs (Real-time Engagement Tracking)

**Purpose:**
Fetching live public sentiment and engagement data from platforms like Twitter/X and Facebook to feed the Dashboard charts.

**Required API Keys:**
*   `TWITTER_BEARER_TOKEN` (Twitter Developer Portal)
*   `FACEBOOK_GRAPH_API_TOKEN` (Meta Developer Portal)

**Where to plug it in:**
1.  **Background Worker / Cron Job**: Social media scraping should not happen on every page load. You should set up a background task (e.g., using Vercel Cron Jobs or a separate Node worker) to fetch data hourly.
2.  **Database Updates**: The cron job will write to your real database.
3.  **Metrics API (`/src/app/api/dashboard/metrics/route.ts`)**: Update this route to fetch the newly aggregated social data from your real database rather than the static `mockSocialPosts`.

---

## Setting up Environment Variables

When you are ready to integrate these services, create a `.env.local` file in the root directory and define the keys:

```env
# OpenAI
OPENAI_API_KEY=your_sk_...

# Mailchimp
MAILCHIMP_API_KEY=your_key...
MAILCHIMP_SERVER_PREFIX=us20

# Database (When moving away from mock-db)
DATABASE_URL=postgres://...
```
